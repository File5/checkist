# Checkist

Перед работой прочитай [AGENTS.md](AGENTS.md) и нужные [architecture](docs/architecture.md), [data-model](docs/data-model.md), [api-contract](docs/api-contract.md), [development](docs/development.md), [verification](docs/verification.md). Сверяй с кодом, compose.yaml и .env.example.

Django/DRF + PostgreSQL, Redis/Celery для health, React/Vite SPA: health, каталог, цены, загрузка фото/задания и чеки подключены к API (docs/frontend.md). Stores/catalog/receipts и admin реализованы. Recognition: фото/MEDIA, PostgreSQL queue, host recognition_worker рядом с Codex CLI или явным fake, detect/crop/recognize/import, cancel/retry, локальный upload/jobs/receipts API со всеми строками. Новые магазины/товары создаются автоматически; SHA-256 replay и повторные фото не дублируют совместимые чеки/строки, заполненные значения не перезаписываются. Needs_review сохраняет результат и причины; человек исправляет и подтверждает такую вырезку: `POST /api/recognition/receipt-images/{id}/confirm/` (правки + подтверждение одной транзакцией через тот же импорт, `recognition/review.py`), форма в карточке вырезки на `/recognition/jobs/{id}`. Отказ ничего не сохраняет (`review_invalid` с issues, `invalid_parameter` с fields, `review_unavailable`/`review_resolved`/`review_busy`/`job_active`); повтор — по содержимому тела; найденный существующий чек не перезаписывается; миграций нет. Промпт v5 просит налоговые evidence: ставка и налоговый итог импортируются только с подтверждением чтения, иначе чек сохраняется без них с замечаниями.

Новый API: DEBUG + ALLOW_LOCAL_RECOGNITION_API=1 + loopback, CSRF даже анониму. Без владельца/пользовательского доступа. Старые 13 GET/health сохраняют контракт. Vite dev/preview: /api и /media на один Django; точный Origin клиента включить в DJANGO_CSRF_TRUSTED_ORIGINS. Native Codex .exe/auth на host, Celery не запускает OCR. `executor.state` idle/busy/absent: простаивающий воркер виден API по его advisory-блокировке (`pg_locks` своей БД), `available` = не absent. API и worker используют одну DB/MEDIA, scratch отдельно.

Дубли товаров: `merges` сливает их предварительно (перенос строк/написаний с журналом), `/api/product-merges/` — список, группа, покупки, detect/confirm/cancel/exclude с доступом recognition; поглощённые скрыты из 13 GET (404), формы прежние. Автопоиск при импорте — `PRODUCT_MERGE_AUTO_DETECT` (по умолчанию 0); перед `migrate merges zero` — `product_merges cancel-pending`; `resolution.py` не трогать. Эталоны — `backend/merges/tests/fixtures/public/`, QA-демо — `seed_product_merge_demo`. Экраны клиента сделаны: `/catalog/merges`, `/catalog/merges/{id}`, пометки в каталоге и карточке (docs/frontend.md); ручная приёмка — `frontend/src/features/merges/ACCEPTANCE.md`.

Облегчённая v1 по-прежнему исключает ReceiptDraft и серверный черновик (правки до подтверждения живут только на странице), MutationRequest/Idempotency-Key, cleanup, POSIX watchdog, manual_locked, защиту stale admin POST от OCR, правку сохранённого чека через API и выбор товара каталога для строки. Не добавляй это без задачи. Дашборд/курсы/production пока не реализованы. Issues вырезки несут reason/severity/context; SPA показывает их группами одним компонентом в задании и чеке.
