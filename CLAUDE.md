# Checkist

Перед работой прочитай [AGENTS.md](AGENTS.md) и нужные [architecture](docs/architecture.md), [data-model](docs/data-model.md), [api-contract](docs/api-contract.md), [development](docs/development.md), [verification](docs/verification.md). Сверяй с кодом, compose.yaml и .env.example.

Django/DRF + PostgreSQL, Redis/Celery для health, React/Vite SPA: health, каталог, цены, загрузка фото/задания и чеки подключены к API (docs/frontend.md). Stores/catalog/receipts и admin реализованы. Recognition: фото/MEDIA, PostgreSQL queue, host recognition_worker рядом с Codex CLI или явным fake, detect/crop/recognize/import, cancel/retry, локальный upload/jobs/receipts API со всеми строками. Новые магазины/товары создаются автоматически; SHA-256 replay и повторные фото не дублируют совместимые чеки/строки, заполненные значения не перезаписываются. Needs_review сохраняет результат и причины; человек исправляет и подтверждает такую вырезку: `POST /api/recognition/receipt-images/{id}/confirm/` (правки + подтверждение одной транзакцией через тот же импорт, `recognition/review.py`), форма в карточке вырезки на `/recognition/jobs/{id}`. Отказ ничего не сохраняет (`review_invalid` с issues, `invalid_parameter` с fields, `review_unavailable`/`review_resolved`/`review_busy`/`job_active`); повтор — по содержимому тела; найденный существующий чек не перезаписывается; миграций нет. Промпт v5 просит налоговые evidence: ставка и налоговый итог импортируются только с подтверждением чтения, иначе чек сохраняется без них с замечаниями.

Новый API: DEBUG + ALLOW_LOCAL_RECOGNITION_API=1 + loopback, CSRF даже анониму. Без владельца/пользовательского доступа. Старые 13 GET/health сохраняют контракт. Vite dev/preview: /api и /media на один Django; точный Origin клиента включить в DJANGO_CSRF_TRUSTED_ORIGINS. Native Codex .exe/auth на host, Celery не запускает OCR. `executor.state` idle/busy/absent: простаивающий воркер виден API по его advisory-блокировке (`pg_locks` своей БД), `available` = не absent. API и worker используют одну DB/MEDIA, scratch отдельно.

Дубли товаров: `merges` сливает их предварительно (перенос строк/написаний с журналом), `/api/product-merges/` — список, группа, покупки, detect/confirm/cancel/exclude с доступом recognition; поглощённые скрыты из 13 GET (404), формы прежние. Автопоиск при импорте — `PRODUCT_MERGE_AUTO_DETECT` (по умолчанию 0); перед `migrate merges zero` — `product_merges cancel-pending`; `resolution.py` не трогать. Эталоны — `backend/merges/tests/fixtures/public/`, QA-демо — `seed_product_merge_demo`. Экраны клиента сделаны: `/catalog/merges`, `/catalog/merges/{id}`, пометки в каталоге и карточке (docs/frontend.md); ручная приёмка — `frontend/src/features/merges/ACCEPTANCE.md`.

Категории новых товаров: `classification` спрашивает модель о товарах из «Не разобрано» и сразу приписывает их к предложенному обобщённому продукту и категории с пометкой «требует подтверждения» (журнал прежнего значения и созданных записей каталога); `/api/product-classifications/` — список, запись, confirm (тот же либо другой обобщённый продукт), reject, массовый confirm, status, runs с доступом recognition; отклонение возвращает товар в «Не разобрано», убирает созданное пустое и повторно тот же вариант не предлагает; содержательный или подтверждённый товар автоматика не меняет. При подтверждении слияния дублей ожидающая запись поглощённого товара переходит к оставляемому, только если тот до слияния был в «Не разобрано» и получил предложенное значение из этого предположения (`after_merge_confirmed(..., target_generic_before)`); иначе запись закрывается `superseded` / `merged`, товар не трогается; сверка запись не переносит никогда. Своя ожидающая запись оставляемого товара закрывается так же (`superseded` / `merged`), если слитый с ним дубль имел то же значение от человека; это решает сверка по журналу слияний. Отклонение и `cancel-pending` не меняют значение, которое было у товара до предположения либо выставлено человеком. Запуск ставит кнопка либо импорт при `PRODUCT_CLASSIFICATION_AUTO_SUGGEST` (по умолчанию 0), исполняет `recognition_worker` пакетами (текстовый вызов Codex без изображения либо fake); сбой модели не трогает чек и каталог. Команды `product_classifications suggest [--dry-run]` / `reconcile` / `cancel-pending`; перед `migrate classification zero` — `cancel-pending`. Эталоны — `backend/classification/tests/fixtures/public/`, QA-демо — `seed_product_classification_demo`, очередь и замер модели — `backend/classification/QUEUE.md`. Клиент: экран `/catalog/classification`, пометки в каталоге и карточке (docs/frontend.md); ручная приёмка — `frontend/src/features/classification/ACCEPTANCE.md`. Осторожно: `codex.exe` в PATH со входом — любой запуск с `codex_cli`, дошедший до провайдера, делает настоящий модельный запрос; в проверках `RECEIPT_OCR_PROVIDER=fake`, в тестах с `codex_cli` — `RECEIPT_OCR_CODEX_EXECUTABLE="nonexistent-checkist-codex"` и подмена запуска процесса.

Статистика, серверная часть: локальные `GET /api/stats/spending/` (траты за период: категории с drill-down, обобщённые продукты, товары, магазины), `/api/stats/receipts/series/` (походы по времени), `/api/stats/receipts/compare/` (изменение среднего чека = количество + цены + состав, индекс Фишера по совпавшим товарам с покрытием) — доступ как у `/api/receipts/`; открытый `GET /api/products/{id}/prices/series/` (ряды цен товара и похожих товаров того же GenericProduct). Без моделей, миграций и индексов; валюты не складываются; «Не разобрано» показывается как есть. Контракт — docs/api-contract.md, эталоны — `backend/api/tests/fixtures/stats/`, демо для QA — `seed_stats_demo`, запуск — docs/development.md. Тесты — через `config.test_runner.Runner` (autovacuum в тестовой БД отключён). Клиент статистики сделан: `/stats` (траты, круговая диаграмма, drill-down), `/stats/receipts` (почему изменился средний чек), «График цен» в карточке товара; свой SVG `frontend/src/lib/charts/`, одна валюта — один блок, состояние в адресе (docs/frontend.md); ручная приёмка — `frontend/src/features/stats/ACCEPTANCE.md`; настоящий HTTP — `frontend/scripts/check_stats_proxy.mjs dev|preview <origin>` на свежей `seed_stats_demo`; `frontend/*-preview/` — статические снимки на эталонах, не приёмка. Только светлая тема; график цен берёт из фильтров карточки только период.
