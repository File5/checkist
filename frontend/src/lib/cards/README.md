# Карточки вместо таблиц, панель действий, токены раскладки

Контракт мобильной раскладки. Порог телефона один — `max-width: 540px` (`PHONE_MAX_WIDTH`). Таблица, её CSS, классы и
тесты на широком экране не меняются: на телефоне компонент рисует **другую разметку** — список карточек.

## Как выбрать вид

```tsx
import { Card, CardList, useNarrow } from '../../lib/cards'

const columns = { date: 'Дата', price: 'Цена', receipt: 'Покупка' } // один источник подписей

export function PriceHistory({ rows }: Props) {
  const narrow = useNarrow()
  return narrow ? <PriceHistoryCards rows={rows} columns={columns} /> : (/* прежний JSX таблицы, <th>{columns.date}</th> */)
}
```

- `useNarrow()` вызывается в том же файле, где стоит `<table`: так его находит `coverage.test.ts`. Сделал карточки —
  **убери свою строку** из `exceptions` в `coverage.test.ts`, иначе тест упадёт.
- В тестах (Node, без `window`) и при серверной отрисовке хук отдаёт `false` — прежние тесты разметки таблиц видят
  таблицу. Карточки проверяй, отрисовав свой `XCards` напрямую.
- Вид выбирается только в ветке с данными: загрузку, пустое и ошибку рисуют прежние блоки.
- В DOM всегда один вид, дублей `id` и радио нет. При пересечении 540 px блок перерисовывается.

## Разметка

```tsx
<CardList label="История цен" caption={…}>          {/* либо labelledBy="id заголовка" */}
  <Card id="receipt-line-3" title={…} facts={facts} footer={…} tone="total" />
</CardList>
```

```html
<div class="ck-cards">
  <p class="ck-cards-caption">…</p>
  <ul class="ck-cards-list" aria-label="…">
    <li class="ck-card" id="…" tabindex="-1" data-tone="total">
      <div class="ck-card-title">…</div>
      <dl class="ck-card-facts">
        <div class="ck-card-fact" data-kind="value"><dt>Дата</dt><dd>…</dd></div>
      </dl>
      <div class="ck-card-footer">…</div>
    </li>
  </ul>
</div>
```

`CardFact = { key, label, value, kind? }`:

| `kind` | Для чего | Поведение |
| --- | --- | --- |
| `value` (по умолчанию) | число, дата, сумма, короткая ссылка | `nowrap`, табличные цифры, вправо; не поместилось рядом с подписью — уходит под неё целиком |
| `text` | свободный текст | перенос по словам |
| `block` | список, `dl` | на всю ширину под подписью |

Правила:

- `label` — текст заголовка колонки из того же массива, что и `<th>` таблицы; двоеточие не добавлять.
- `title` — прежнее содержимое `th` строки, со ссылкой и пометками. Это не заголовок `h*`.
- Порядок фактов — порядок колонок. Нет значения (нет радио, нет кнопки) — передай `null`, `undefined`, `false` или `''`:
  пара не рисуется. Ноль рисуется. Прочерк «—» и слова вроде «Нет покупок» — обычное значение, как в таблице.
- `id` — только у карточки-цели ссылки (`#receipt-line-N`); с ним карточка получает `tabIndex={-1}` и подсветку `:target`.
- `footer` — действия строки: те же кнопки и ссылки с прежними обработчиками и `aria-label`.
- `tone="total"` — карточка итога (строка `tfoot`): значения жирные.
- Числа и даты — только `lib/format.ts` и `lib/text.ts`, даты в `<time dateTime>`.
- Своих стилей карточкам не пиши: нет `@media`, `font-size`, `order`. Не хватает правила — это дефект контракта, верни
  в К0, CSS экрана не правь.

## Панель действий

Добавь `ck-action-bar` вторым классом существующей обёртки кнопок, больше ничего:

```tsx
<div className="stats-actions ck-action-bar">…</div>
```

- Действует только при `(max-width: 540px) and (min-height: 480px)`; шире и ниже — обёртка как была.
- `position: sticky` у низа окна, в потоке своей формы: прилипает, пока форма длиннее экрана, в конце встаёт на место.
  Область прилипания — ближайший родитель; между панелью и окном не должно быть предка с `overflow`.
- В панели только кнопки. Пояснения (`aria-describedby`) и сообщения об отказе остаются вне её.
- Панель добавляет обёртке поля 10 px сверху и снизу, верхнюю рамку и фон `--ck-surface`.
- Стили — `src/components/ActionBar.css`, подключён в `main.tsx` после `App.css`. Правил состояний там нет.

## Токены раскладки (`theme/tokens.css`, `:root`)

| Токен | Значение | Кто меняет |
| --- | --- | --- |
| `--ck-bottom-nav-height` | `0px` | нижняя навигация — в своём узком блоке `App.css`, **на `:root`** (иначе `--ck-bottom-occupied` не пересчитается); высота без полосы жестов |
| `--ck-safe-bottom` | `env(safe-area-inset-bottom, 0px)` | никто; отличен от нуля только при `viewport-fit=cover` |
| `--ck-bottom-occupied` | навигация + полоса жестов | никто; от него отсчитывай всё, что стоит у низа окна |
| `--ck-action-bar-room` | `128px` | никто; место под панель действий |
| `--ck-z-action-bar` | `10` | — |
| `--ck-z-bottom-nav` | `20` | — |
| `--ck-z-menu-sheet` | `30` | — |
| `--ck-z-skip-link` | `40` | — |

`html { scroll-padding-bottom }` — одно на проект, в `ActionBar.css` (место панели + `--ck-bottom-occupied`); второго не
писать, это сторожит `action-bar-css.test.ts`. Оно стоит в блоке панели, то есть при высоте окна меньше 480 px не действует.
Закреплённые ячейки таблиц и плашка результата остаются на `z-index: 1`.

## Не проверено

Тесты — текст правил и разметка в Node. Как карточка помещается на 320 и 375 px, прилипание панели, клавиатура
телефона, чтение с экрана и Safari на iPhone проверяет человек.
