# Ф2: экраны слияния дублей — приёмка

Экраны `/catalog/merges` и `/catalog/merges/{id}`, пометки в каталоге и карточке товара, подсказка для слитого товара. Описание экранов и состояний — [docs/frontend.md](../../../../docs/frontend.md#слияние-дублей-товаров-ф1ф2), контракт — [docs/api-contract.md](../../../../docs/api-contract.md#реализовано-локальный-api-слияния-дублей-товаров-с2).

**Интерфейс в браузере агент не открывал**: автоматический обход UI в проекте запрещён. Визуальное и интерактивное поведение (клики, фокус, клавиатура, screen reader, узкий экран, Back/Forward) принимает человек по сценарию ниже.

## Запуск QA-сервера и клиента

Нужна **чистая** QA-база: демо-названия не должны совпадать с существующими товарами. Dev-базу не использовать. PowerShell из корня репозитория; в каждом терминале — весь блок:

```powershell
$env:POSTGRES_DB = "checkist_qa"
$env:POSTGRES_HOST = "127.0.0.1"
$env:POSTGRES_PORT = "25432"
$env:REDIS_PORT = "16379"
$env:CELERY_BROKER_URL = "redis://127.0.0.1:16379/0"
$env:CELERY_RESULT_BACKEND = "redis://127.0.0.1:16379/1"
$env:DJANGO_CACHE_URL = "redis://127.0.0.1:16379/2"
$env:VITE_API_BASE_URL = "/api"
$env:DEV_API_PROXY_TARGET = "http://127.0.0.1:18000"
$env:DJANGO_DEBUG = "1"
$env:ALLOW_LOCAL_RECOGNITION_API = "1"
$env:PRODUCT_MERGE_AUTO_DETECT = "1"
$env:DJANGO_CSRF_TRUSTED_ORIGINS = "http://127.0.0.1:15173,http://localhost:15173"
$env:MEDIA_ROOT = Join-Path $env:TEMP "checkist-qa-recognition-media"
$env:RECEIPT_OCR_TEMP_ROOT = Join-Path $env:TEMP "checkist-qa-recognition-scratch"
```

Терминал 1 — сервер (`.env` и `backend/.venv` подготовлены по [docs/development.md](../../../../docs/development.md)):

```powershell
docker compose -p checkist_qa up -d --wait --wait-timeout 90 postgres redis
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py migrate --noinput
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py seed_product_merge_demo
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py product_merges detect
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py runserver 127.0.0.1:18000 --noreload
```

Терминал 2 — клиент:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev -- --port 15173
# либо собранное приложение: npm.cmd run build; npm.cmd run preview -- --port 15173
```

Открыть `http://127.0.0.1:15173/catalog/merges`. Если том `checkist_qa` уже содержит другие данные, взять отдельный Compose-проект, порты и базу с именем `checkist_qa_<суффикс>` и согласованно заменить их во всех переменных, включая `DEV_API_PROXY_TARGET` и `DJANGO_CSRF_TRUSTED_ORIGINS` (точный origin Vite с портом). После приёмки остановить свои `runserver` и Vite, затем `docker compose -p checkist_qa down` без `-v`.

## Ручной сценарий (человек)

1. `http://127.0.0.1:15173/catalog/merges`: 7 групп, у группы 1 — «Есть конфликт данных». Нажать «Найти дубли»: «Новых дублей не найдено», список прежний. В шапке раздела — «Товары» / «Дубли».
2. Группа 2 (пицца): три записи, оставляемая — №2 «Steinhof.PizzaSpezial»; в «Покупках группы» четыре строки с напечатанными названиями и исходными записями (№2, №9, №15). Ссылка названия записи №2 → карточка `/catalog/products/2`: блок «Предварительно объединено 3 написания — требует подтверждения», четыре покупки в истории, последняя 01.10.2026 по 3,49 EUR. В каталоге по запросу `pizza` — две карточки (№3 и №2), у №2 значок «Дубли: требует подтверждения». `/catalog/products/9` — «Товар объединён с «Steinhof.PizzaSpezial»» и ссылка на группу 2.
3. Открыть чек №8 (`/receipts/8`): названия строк, суммы и позиции прежние; строка «Steinhof PizzaSpezial» ведёт на товар №2.
4. В группе 2 нажать «Отменить слияние»: состояние «Отменено», кнопок нет, покупок в группе нет. Карточки №2, №9, №15 снова раздельны, у каждой свои покупки; значка в каталоге нет. «Найти дубли» эту группу не возвращает.
5. Группа 1 (молоко): блок «Обобщённый продукт» с двумя значениями, «Подтвердить слияние» недоступна, подпись называет недостающее поле. Пока группа ожидает, `/catalog/products/13` показывает подсказку со ссылкой на группу. Выбрать «Молоко», оставить запись №1, подтвердить: «Подтверждено», кнопок и выбора нет. `/catalog/products/6` — «Товар объединён с «GQ EgSB H-Milch 1,5%»» и ссылка на товар №1; у товара №1 обобщённый продукт «Молоко».
6. Группа 7: «Исключить из группы» у записи №22. Она снова отдельная карточка `/catalog/products/22`; в группе остались №11 и №20, запись №22 помечена «исключена из группы».
7. Остановить `runserver`, выполнить `$env:ALLOW_LOCAL_RECOGNITION_API = "0"` и запустить его снова. Каталог и карточки работают без пометок и без сообщений об ошибке; `/catalog/merges` и `/catalog/merges/7` сообщают «Локальный API выключен…» с кнопкой «Повторить», «Найти дубли» недоступна. Вернуть `1` и перезапустить.
8. Клавиатура и адаптив на экранах групп: Tab/Shift+Tab по фильтру, кнопкам, радио «Оставить», select названия, значениям конфликта; Space/Enter; видимая рамка фокуса; после действия фокус на нажатой кнопке либо на сообщении о результате; область таблицы фокусируется и прокручивается стрелками. Ширины 320 / 375 / 768 / 1280 px и zoom 200%: страница не прокручивается по горизонтали, прокручивается только таблица. Back/Forward между списком (с фильтром `?status=all`) и группой, перезагрузка обоих экранов, «К списку групп» возвращает тот же фильтр. Screen reader: единственный h1, подписи таблиц и полей, сообщение о результате действия.
9. Админка `http://127.0.0.1:18000/admin/` (пользователь — `manage.py createsuperuser`): товар из ожидающей группы удалить нельзя; после подтверждения написания и строки указывают на оставляемый товар; приёмка F4/F6 по `docs/verification.md` — без изменений.

Дополнительно, двумя вкладками с одной и той же группой:

- **`merge_changed`** — совместить с шагом 6: открыть группу 7 во вкладках А и Б, в А исключить запись №22, в Б (без перезагрузки) выбрать другую оставляемую запись и нажать «Подтвердить слияние» → «Состав группы изменился…», состав обновлён, выбор сброшен к значениям по умолчанию, ничего не подтверждено.
- **`merge_resolved`** — группа 6: во вкладке А «Отменить слияние», во вкладке Б нажать «Подтвердить слияние» → «Слияние уже завершено…», показано «Отменено», кнопок нет.
- **Отказ сети**: в DevTools включить Offline и нажать «Отменить слияние» → «Ответ сервера не получен. Действие могло выполниться…»; повтор — только новым нажатием после Online.

## Ограничения и непроверенное

- Работа React в браузере не проверялась: клики и ввод, фактический фокус и его возврат, клавиатура, screen reader, вёрстка на узком экране и при zoom 200%, Back/Forward, cookie-политика браузера для CSRF. Шаги 1–9 выше.
- `merge_busy` на настоящем сервере не воспроизводился: нужен импорт чека или другое слияние в тот же момент. Текст, отсутствие автоповтора и кнопка «Повторить» проверены тестами на эталонном ответе `error-merge-busy.json`.
- `merge_conflict` с `fields.name` / `fields.gtin` (совпадение с посторонним товаром) в демо-данных не возникает: проверен только тестом разметки.
- Пометки каталога читают одну страницу до 200 ожидающих групп; запрос пометок повторяется при каждом открытии списка и карточки, без кеша.
- Страницы покупок группы (больше 50 строк) и страницы списка групп (больше 50 групп) на демо-данных не возникают: проверены тестами разметки.
- Подтверждение необратимо и выполняется одним нажатием, без дополнительного диалога: предупреждение показано подписью под кнопкой.
