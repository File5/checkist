# F4: карточка товара и история цен

Реализован компонент страницы товара: карточка и путь категории, история покупок с серверной пагинацией, фильтры в URL, поиск магазинов и отдельная серверная сводка. Все четыре запроса имеют независимые состояния. Ошибки 400 предлагают исправить поля; выход страницы за диапазон предлагает первую страницу; отказ отдельного блока сохраняет остальные данные.

Этот файл — описание реализации и сценарий приёмки. Скриншоты и визуальная проверка не выполнялись. Автоматический обход браузера запрещён проектом. Статического макета с вымышленными данными нет.

## Подключение в F5

```tsx
import ProductPage from './features/product/ProductPage'

<ProductPage productId={route.productId} query={route.query} returnTo={returnTo} />
```

`ProductPage.tsx` экспортирует страницу по умолчанию. Props соответствуют `ProductPageProps` из `src/pages/types.ts`: `productId: number`, `query: HistoryQuery`, `returnTo?: string`. CSS импортируется самой страницей; все собственные классы имеют префикс `product-`. Единственный h1, заголовок документа и фокус при смене pathname принадлежат оболочке F2. `PriceHistory`, `PriceSummary`, `StoreFilter` — внутренние default exports в одноимённых файлах.

App.tsx и интерфейсы F1/F2 не изменялись: до подключения в F5 адрес товара показывает заглушку F2. Сборка F4 проверена TypeScript; текущий bundle использует каркас с заглушками. Предпросмотр готового маршрута и реальный HTTP каталога требуют интеграции F5 и backend по контракту `5e1adfa`.

## Проверено и не прошло

Первые `npm.cmd run lint` и `npm.cmd run build` — каждый exit 1: неиспользуемые импорты `fieldMessages` и `FilterDraft` в ProductPage.tsx. Импорты удалены. Повторные проверки окончательного кода прошли с exit 0; тесты не отключались, ожидания не ослаблялись.

## Не проверено и почему

- Настоящие GET каталога, proxy, QA-данные: backend ещё не слит в эту ветку, по задаче его не запускали и не меняли соседний worktree. После подключения F5 использовать изолированную QA и HTTP/CLI-проверку F5 против контрактного backend.
- Визуальная, интерактивная, клавиатурная приёмка и screen reader: выполняет человек после подключения страницы в F5. Ни Node-render, ни build не подтверждают этот результат.
- Production hosting, deployment и merge не выполнялись.

## Ручной сценарий после подключения F5

Подготовить свободную изолированную QA по `docs/verification.md`, с backend каталога, миграциями и вымышленными данными. Применить весь QA environment-блок в каждом терминале, включая `VITE_API_BASE_URL=/api` и `DEV_API_PROXY_TARGET=http://127.0.0.1:18000`. Не записывать в dev/локальный Postgres. После подключения в App запустить в `frontend/`:

```powershell
npm.cmd run dev -- --port 15173
```

1. Получить ID товара из QA API, пройти каталог → категорию → товар на `http://127.0.0.1:15173/catalog/products/<id>`. Сверить название, бренд, модель, GTIN, фасовку, обобщённый продукт и category.path с карточкой API. Пустые поля дают «Не указано», произвольные attributes не показаны. «Назад к списку» сохраняет исходный URL; при прямом входе есть «Назад в категорию».
2. Сверить строки истории и сводку с API. В Network история имеет `ordering=-observed_at`, сводка — `group_by=store&price=paid&interval=none`. У сводки отсутствуют page и page_size. Проверить отрицательную/нулевую цену, normalized=null, comparable=false и нормализованную единицу, отличную от базовой. Валюты/единицы остаются отдельными группами; подписи ограничений видны.
3. Выбрать страну/валюту/магазин, задать период и нажать «Применить фильтры». URL хранит фильтры, первая страница подразумевается. Перейти на следующую страницу, изменить фильтр и применить — page снова 1. «Сбросить фильтры» убирает все фильтры и page. Ввести начало позже конца — ошибки обоих полей, фокус на первом ошибочном поле, новые запросы истории/сводки не отправляются. Исправить диапазон и применить.
4. Поиск магазина: ввести минимум 2 символа и нажать Enter или «Найти», выбрать найденный магазин в native select и применить фильтры. Проверить поиск с пустым полем, пустой результат и следующую страницу справочника на наборе >50 точек. Начальные варианты из карточки остаются доступны; список не объявлен полным. В запрос /stores/ уходят только country/q/page/page_size. Выбор магазина без покупок этого товара даёт пустую историю.
5. Скопировать URL с фильтрами и страницей, открыть напрямую, перезагрузить. Back/Forward восстанавливают применённые фильтры и данные. Неизвестный товар даёт «Товар не найден» со ссылкой в каталог. Заведомо большая page даёт действие «На первую страницу» с сохранением фильтров. Товар без покупок — «Покупок этого товара пока нет»; пустой результат активного фильтра — «Нет записей по выбранным фильтрам».
6. Через DevTools блокировать отдельно history, затем summary, затем /stores/. Карточка и остальные запросы сохраняются; каждый блок показывает собственную ошибку/повтор. При отказе /stores/ select магазина недоступен, остальные фильтры и история работают; выбранный магазин можно убрать. Для точек без полного Store остаются name/city/country, момент подписан UTC. Снять блокировку и нажать локальный «Повторить».
7. Slow network: быстро применить два фильтра, переключить страницы или уйти из товара. Поздний ответ не подменяет новые данные и отмена не становится ошибкой. Проверить Offline → Online → «Повторить» и задержку ответа >15 секунд → timeout → повтор. Во время загрузки своего блока прошлые строки другого фильтра не показаны.
8. Только клавиатурой пройти ссылки, поля, поиск магазина, применение, сброс и повтор. Проверить видимый фокус и его положение после загрузки/перехода/ошибки. Screen reader читает labels, aria-invalid/описания ошибок, caption и заголовки таблицы. Tab переводит фокус на подписанный контейнер таблицы, стрелки прокручивают его горизонтально.
9. Проверить 320/375/768/1280 px и zoom 200% с длинными именами, GTIN и адресами. Действия видны, числа выровнены, горизонтальная прокрутка есть только внутри таблицы, вертикальная — у страницы. Проверить loading без скачка/обрезания действий. Анимаций в F4 нет. Повторить общий ручной сценарий `docs/verification.md`, включая health после интеграции оболочки.

После приёмки остановить только свои Vite/API-процессы и собственный QA Compose project командой `down` без `-v`; тома сохранить. Не останавливать чужие процессы.
