# Экран входа `/login` — приёмка

Экран входа без серверной части: логотип слева, форма справа. Авторизации в проекте ещё нет — форма проверяет только пустые поля, запрос не отправляет и отвечает «Вход пока не подключён: пропускной режим не введён».

**Интерфейс в браузере агент не открывал**: автоматический обход UI в проекте запрещён. Вид в обеих темах, клавиатуру, фокус, экранный диктор и узкий экран принимает человек по сценарию ниже.

## Файлы

| Файл | Что |
| --- | --- |
| `index.tsx` | именованный экспорт `LoginPage`, подключение `Login.css` |
| `LoginPage.tsx` | `LoginPage` (состояние, фокус, отправка) и `LoginView` (вся разметка для заданного состояния) |
| `login-state.ts` | модель: исходы, тексты, проверка пустых полей, хранилище одной формы |
| `Login.css` | стили; цвета только из `theme/tokens.css`, классы `ck-login-*` |
| `login-state.test.ts`, `login-markup.test.tsx`, `login-css.test.ts` | 63 теста: модель, серверная разметка в Node, текст правил CSS |
| `preview/` | `index.html` — автономная страница с настоящим компонентом; `build.mjs`, `demo.tsx`, `entry.tsx` — её сборка |

## Договор с оболочкой приложения

`LoginPage` не требует пропсов и сам рисует `<main class="ck-login">`, единственный `h1#page-heading` с `tabIndex={-1}`, переключатель темы и ссылку в каталог. Шапку, навигацию, подвал, ссылку «К содержимому» и свой `h1` приложение вокруг него не рисует. Фон страницы экран закрашивает сам (`--ck-bg`, не ниже высоты окна).

## Точка стыка с будущей авторизацией

Экран сам ничего не отправляет. `LoginPage` принимает необязательный обработчик:

```ts
onSubmit?: (login: string, password: string) => Promise<'ok' | 'invalid' | 'throttled' | 'unavailable' | 'network'>
```

По умолчанию подставлен `unavailableHandler` из `login-state.ts`: запроса нет, исход `unavailable`. Задача авторизации передаёт настоящий обработчик (`<LoginPage onSubmit={…} />`), который отправляет данные на сервер и переводит ответ в один из пяти исходов; экран, тексты и состояния менять не нужно.

| Исход | Что видит человек |
| --- | --- |
| `ok` | «Вход выполнен. Открываем каталог…», затем переход в `/catalog` с заменой записи истории (`onEnter`, по умолчанию `navigate('/catalog', { replace: true })`) |
| `invalid` | «Неверный логин или пароль» |
| `throttled` | «Слишком много попыток. Повторите позже» |
| `unavailable` | «Вход пока не подключён: пропускной режим не введён» и ссылка «Пройти в каталог» |
| `network` | «Не удалось связаться с сервером. Повторите попытку» |

Обработчик, который бросил исключение, отклонил обещание или вернул неизвестное значение, считается исходом `network`. Логин передаётся как введён (без обрезки пробелов). Поля неуправляемые: пароль живёт только в своём `<input>`, читается в момент отправки и передаётся обработчику; в состояние, хранилище браузера и консоль он не попадает. Обработчик авторизации должен соблюдать то же.

## Решения, которые стоит посмотреть глазами

- **Кнопка во время отправки** помечена `aria-disabled="true"`, а не `disabled`: фокус клавиатуры остаётся на ней, повторную отправку (нажатием и Enter в поле) отклоняет модель. Выглядит как недоступная, подпись «Входим…».
- **Лучи на доске** — CSS-градиент, затухающий к эмблеме; логотип наложен режимом `mix-blend-mode: lighten`, чтобы его тёмный квадрат не был виден поверх лучей. Проверить, что вокруг логотипа нет видимого квадрата и что лучи не пачкают тёмные места самой эмблемы. Если мешают — правило `.ck-login-rays` можно убрать, остальное не зависит от него.
- **Сообщение формы** стоит под кнопкой «Войти», чтобы ссылка «Пройти в каталог» шла в порядке Tab сразу после кнопки.
- **Тон «вход не подключён»** — сведения (синий), не ошибка: человек ничего не сделал неверно.
- Ироничных фраз на экране две: «Предъявите пропуск» и «Пропуска выдаёт администратор» (третья, «пропускной режим не введён», задана текстом сообщения).

| Команда | Результат |

| `npm.cmd run lint` | exit 0 |

Тесты идут в Node без `window`: модель и серверная разметка (`renderToStaticMarkup`). Они **не** проверяют работу в браузере: перенос фокуса, отправку по Enter, отсутствие сетевых запросов, вид, контраст, адаптив.

На момент сдачи маршрут `/login` в приложение ещё не подключён (его добавляет соседняя подзадача в `App.tsx`), поэтому `npm.cmd run build` экран в сборку не включает; сам экран собран отдельно страницей превью.

## Превью без сервера

`preview/index.html` — одна автономная страница (стили, скрипт, логотип и шрифт внутри, сети не нужно) с настоящим `LoginPage`. Полоса над экраном выбирает, что ответит обработчик входа: «как в приложении сейчас» либо любой из пяти исходов с задержкой 1,5 с; «Сбросить экран» монтирует экран заново. Переключатель темы работает. Ссылки в каталог в превью никуда не ведут: приложения вокруг нет. Полоса — часть превью, а не экрана: в порядке Tab она идёт первой.

Страница — снимок: после правки экрана пересобрать `node src/features/login/preview/build.mjs`. Превью не заменяет приёмку в приложении: адрес `/login`, фокус на заголовке при переходе и переход в каталог проверяются только там.

## Ручная приёмка в приложении

Нужен только клиент, сервер не требуется. PowerShell из `frontend/`:

```powershell
npm.cmd ci
npm.cmd run dev -- --port 15173
# либо собранное приложение: npm.cmd run build; npm.cmd run preview -- --port 15173
```

Открыть `http://127.0.0.1:15173/login` (маршрут появляется после слияния подзадачи оболочки). После приёмки остановить Vite.

### 1. Вид, обе темы

1. Тёмная тема (по умолчанию): слева крупный логотип на тёмной доске с золотой рамкой, справа «ЧЕКИСТ» прописными, «Продуктовая разведка», золотая линия со звездой, «Предъявите пропуск», поля «Логин» и «Пароль» с подписями, красная кнопка «Войти», под формой «Пропуска выдаёт администратор», ссылка «Каталог продуктов» и кнопка «Тема: тёмная». Шапки, меню и подвала приложения нет.
2. Вокруг логотипа не виден квадрат картинки; лучи на доске не мешают читать логотип.
3. Нажать «Тема: тёмная» → светлая тема: страница бумажного цвета, доска с логотипом осталась тёмной, текст читается, кнопка «Войти» красная с белым текстом, ссылка тёмно-красная. Красного текста в тёмной теме нет.
4. Обновить страницу — тема сохранилась. Вернуть тёмную.

### 2. Пустая отправка

1. Не заполняя поля, нажать «Войти». Фокус в поле «Логин»; у обоих полей утолщённая рамка, под каждым значок и текст «Введите логин» / «Введите пароль».
2. Ввести логин — ошибка логина исчезла сразу. Нажать Enter: фокус в поле «Пароль», ошибка осталась только у него.
3. Вкладка «Сеть» разработчика всё это время пуста: запросов нет.

### 3. Заполненная отправка

1. Открыть вкладку «Сеть», очистить её. Ввести логин и пароль, нажать Enter в поле «Пароль».
2. Под кнопкой сообщение со значком: «Вход пока не подключён: пропускной режим не введён. Пройти в каталог». Кнопка «Войти» снова доступна.
3. Во вкладке «Сеть» — ни одного запроса. В адресной строке по-прежнему `/login` без параметров: ни логина, ни пароля в адресе нет.
4. В хранилище сайта (Application → Local/Session Storage, Cookies) пароля нет; в консоли ничего не напечатано.
5. «Пройти в каталог» открывает каталог; «Назад» возвращает на `/login`.

### 4. Остальные исходы

Исходы `invalid`, `throttled`, `network`, `ok` и состояние отправки в приложении пока вызвать нечем — их показывает превью (`preview/index.html`, список «Ответ на „Войти“»):

1. Любой исход с задержкой: после отправки полторы секунды кнопка серая с подписью «Входим…», повторное нажатие и Enter в поле ничего не делают, фокус не теряется.
2. `invalid` — «Неверный логин или пароль», `network` — «Не удалось связаться с сервером. Повторите попытку» (тон ошибки); `throttled` — «Слишком много попыток. Повторите позже» (оранжевый тон). У каждого сообщения значок и полоса слева, не только цвет. После ответа кнопка снова доступна.
3. `ok` — «Вход выполнен. Открываем каталог…», кнопка остаётся недоступной, в полосе превью счётчик «Переходов в каталог: 1».
4. Во время отправки нажать «Сбросить экран»: форма исходная, поздний ответ ничего не меняет, в консоли нет предупреждений.

### 5. Клавиатура

1. Перейти на `/login` из приложения либо обновить страницу, нажимать Tab: логин → пароль → «Войти» → «Каталог продуктов» → «Тема: …». После сообщения «вход не подключён» между «Войти» и «Каталог продуктов» добавляется «Пройти в каталог».
2. Кольцо фокуса видно на каждом элементе в обеих темах, в том числе вокруг красной кнопки в светлой теме.
3. Enter в любом поле отправляет форму; пробел и Enter на «Войти» — тоже. Shift+Tab идёт в обратном порядке.

### 6. Узкий экран и масштаб

1. Ширина 768 px: две колонки, логотип слева, форма справа, ничего не обрезано.
2. Ширина 375 px и 320 px: логотип сверху и занимает не больше трети высоты окна, форма под ним; горизонтальной прокрутки нет, кнопка и ссылки не уезжают за край; до низа формы можно докрутить.
3. Повторить пустую отправку на 320 px: тексты ошибок переносятся, поле не шире экрана.
4. Масштаб браузера 200 % на обычном окне: раскладка переходит в одну колонку, всё доступно прокруткой по вертикали, горизонтальной прокрутки нет.

### 7. Экранный диктор

1. Заголовок страницы читается как «Чекист», заголовок первого уровня один. Логотип читается как «Чекист — продуктовая разведка»; лучи, линия со звездой и значки не читаются.
2. Поля объявляются «Логин» и «Пароль» (обязательные), форма — «Вход».
3. Пустая отправка: фокус в первом пустом поле, диктор называет поле недопустимым и читает «Введите логин» / «Введите пароль».
4. Заполненная отправка: сообщение под кнопкой читается само, без перемещения фокуса (область `role="status"`).
5. Во время отправки (превью) кнопка объявляется недоступной.

### 8. Режим высокой контрастности

Включить в системе режим высокой контрастности (Windows): поля, кнопка, сообщение и кольцо фокуса различимы, лучи скрыты.
