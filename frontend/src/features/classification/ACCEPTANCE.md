# Категории товаров: экран и пометки — приёмка

Экран `/catalog/classification` (Ф1), пометки «требует подтверждения» в списке товаров и в карточке товара (Ф2). Описание экрана, запросов и состояний — [docs/frontend.md](../../../../docs/frontend.md#категории-товаров-предположение-с-подтверждением-ф1ф2), контракт — [docs/api-contract.md](../../../../docs/api-contract.md#реализовано-локальный-api-предположений-категорий-товаров), запуск сервера — [docs/development.md](../../../../docs/development.md#qa-предположения-категорий-для-клиента).

**Интерфейс в браузере агент не открывал**: автоматический обход UI в проекте запрещён. Визуальное и интерактивное поведение (клики, фокус, клавиатура, screen reader, узкий экран, Back/Forward) принимает человек по сценарию ниже.

## Запуск QA-сервера и клиента

Нужна **чистая** QA-база: демо-названия не должны совпадать с существующими товарами. Dev-базу не использовать. PowerShell из корня репозитория; в каждом терминале — весь блок:

```powershell
$env:POSTGRES_DB = "checkist_qa"
$env:POSTGRES_HOST = "127.0.0.1"
$env:POSTGRES_PORT = "25432"
$env:REDIS_PORT = "16379"
$env:CELERY_BROKER_URL = "redis://127.0.0.1:16379/0"
$env:CELERY_RESULT_BACKEND = "redis://127.0.0.1:16379/1"
$env:DJANGO_CACHE_URL = "redis://127.0.0.1:16379/2"
$env:VITE_API_BASE_URL = "/api"
$env:DEV_API_PROXY_TARGET = "http://127.0.0.1:18000"
$env:DJANGO_DEBUG = "1"
$env:ALLOW_LOCAL_RECOGNITION_API = "1"
$env:RECEIPT_OCR_PROVIDER = "fake"
$env:PRODUCT_MERGE_AUTO_DETECT = "0"
$env:PRODUCT_CLASSIFICATION_AUTO_SUGGEST = "0"
$env:DJANGO_CSRF_TRUSTED_ORIGINS = "http://127.0.0.1:15173,http://localhost:15173"
$env:MEDIA_ROOT = Join-Path $env:TEMP "checkist-qa-recognition-media"
$env:RECEIPT_OCR_TEMP_ROOT = Join-Path $env:TEMP "checkist-qa-recognition-scratch"
```

`RECEIPT_OCR_PROVIDER = "fake"` обязателен: с `codex_cli` воркер делает настоящие модельные запросы.

Терминал 1 — сервер (`.env` и `backend/.venv` подготовлены по [docs/development.md](../../../../docs/development.md)):

```powershell
docker compose -p checkist_qa up -d --wait --wait-timeout 90 postgres redis
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py migrate --noinput
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py seed_product_classification_demo
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py product_classifications suggest --fake-scenario mixed
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py runserver 127.0.0.1:18000 --noreload
```

Терминал 2 — клиент:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev -- --port 15173
# либо собранное приложение: npm.cmd run build; npm.cmd run preview -- --port 15173
```

Терминал 3 — воркер, **только на шаге 8** (тот же блок окружения):

```powershell
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py recognition_worker --fake-scenario success2 --classification-fake-scenario mixed
```

Открыть `http://127.0.0.1:15173/catalog/classification`. Если том `checkist_qa` уже содержит другие данные, взять отдельный Compose-проект, порты и базу с именем `checkist_qa_<суффикс>` и согласованно заменить их во всех переменных, включая `DEV_API_PROXY_TARGET` и `DJANGO_CSRF_TRUSTED_ORIGINS` (точный origin Vite с портом). После приёмки остановить свои `runserver`, воркер и Vite, затем `docker compose -p checkist_qa down` без `-v`.

## Ручной сценарий (человек)

1. **Экран.** `http://127.0.0.1:15173/catalog/classification`: заголовок «Категории товаров»; в шапке раздела — «Товары» / «Дубли» / «Категории», текущая — «Категории». Блок «Предположение категорий»: «Ожидают подтверждения: 9. Без категории: 1.», строка «Запуск завершён: предложено 9, не распознано 1, пропущено 0.», кнопка «Предложить категории» доступна. Ниже фильтр «Ожидают / Подтверждённые / Отклонённые / Заменённые / Все» и блок «Ожидают · Страница 1»: 7 групп из таблицы. У созданных механизмом обобщённых продуктов — пометка «новый», у созданных категорий в пути — «новая»; у «Молоко» пометок нет. У каждой записи — название-ссылка на карточку, написание в чеке с магазином, кнопки «Подтвердить», «Выбрать другой», «Отклонить»; у групп «Кефир» и «Колбаса» — «Подтвердить все (2)».
2. **Значок в каталоге.** `/catalog`: 12 товаров, значок «Категория: требует подтверждения» у девяти (№2–№10), у №1, №11 и №12 значка нет. Значок у «Demo Mettwurst fein» ведёт на `/catalog/classification?product=6`: блок «Записи товара №6 · Ожидают · Страница 1», одна группа «Колбаса» с одной записью и строкой «Показано 1 из 2: остальные у других товаров», ссылка «Показать записи всех товаров». Back возвращает в каталог на то же место. То же в категории (`/catalog/categories/{id}`) и в поиске каталога (`/catalog?q=Demo`).
3. **Блок в карточке.** `/catalog/products/6`: под фактами товара блок «Категория предложена автоматически: „Колбаса“ (Продукты питания → Мясные продукты) — требует подтверждения. Товар уже участвует в сравнении цен по этому обобщённому продукту.» и ссылка «Открыть в списке категорий» на `/catalog/classification?product=6`. В фактах карточки «Обобщённый продукт» — «Колбаса», в пути категории — «Каталог», «Продукты питания», «Мясные продукты». У `/catalog/products/1` и `/catalog/products/11` блока нет. Остальная карточка (фильтры, история, сводка) работает как раньше.
4. **Подтвердить.** На экране у «Demo Frischmilch 1,5%» нажать «Подтвердить»: сообщение «Категория подтверждена.», запись исчезла из ожидающих, счётчик «Ожидают подтверждения: 8». В каталоге у №2 значка нет, в карточке `/catalog/products/2` блока нет, обобщённый продукт — «Молоко». Фильтр «Подтверждённые» показывает запись с состоянием «Подтверждено», что было предложено, итог и время решения.
5. **Подтвердить все.** В группе «Кефир» нажать «Подтвердить все (2)»: открывается область «Подтвердить 2 товара как „Кефир“?» с «Да, подтвердить» и «Отмена», фокус переходит в неё. «Отмена» закрывает область и возвращает фокус на «Подтвердить все (2)». Повторить и подтвердить: «Подтверждено 2 из 2», группа исчезла, значков у №3 и №4 нет.
6. **Выбрать другой.** У «Demo Butterkäse Sch.» нажать «Выбрать другой»: область с полем «Поиск обобщённого продукта» (фокус в нём) и радио-вариантами; «Не разобрано» и сам «Сыр» не предлагаются; один символ в поиске — «Для поиска нужно не меньше 2 символов.». Найти `Мол`, выбрать «Молоко», «Применить выбор»: «Выбран другой обобщённый продукт: «Молоко».». В карточке `/catalog/products/5` обобщённый продукт — «Молоко», блока нет; созданный «Сыр» из каталога исчез.
7. **Отклонить.** У «Demo Salami Sticks» нажать «Отклонить» → «Отклонить предложение? Товар вернётся в „Не разобрано“.» → «Да, отклонить»: «Предложение отклонено: товар возвращён в «Не разобрано».», счётчик «Без категории» вырос на 1; у №7 значка и блока нет, «Колбаса» с товаром №6 осталась. Отклонить и «Demo Mettwurst fein»: обобщённый продукт «Колбаса» и категория «Мясные продукты» из каталога исчезли. Фильтр «Отклонённые» показывает обе записи, «Все» — все девять с их состояниями.
8. **Кнопка запуска, воркер и опрос.** Перед шагом открыть экран во второй вкладке Б и больше её не трогать (она понадобится в пункте «повторное нажатие»). Воркер не запущен.
   - **Очередь без воркера.** Во вкладке А нажать «Предложить категории»: «Запуск поставлен в очередь.», предупреждение «Запуск в очереди. Воркер распознавания не запущен: запуск начнётся, когда воркер запустят.», кнопка недоступна.
   - **Между пакетами, воркер остановлен.** В терминале 3 выполнить `$env:PRODUCT_CLASSIFICATION_BATCH_SIZE = "1"` и один проход `./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py recognition_worker --once --classification-fake-scenario mixed` (печатает `Classification run 2: queued` и завершается). **Не перезагружая** вкладку А, в течение 2–3 секунд увидеть предупреждение «Запуск приостановлен: обработано 1 из 3. Воркер распознавания не запущен: запуск продолжится, когда воркер запустят.». Сообщений «Не удалось обновить данные…» и «Ответ сервера не соответствует ожидаемому формату…» быть не должно, счётчики остаются на месте, кнопка недоступна, текста «начнётся» нет.
   - **Открытие страницы в этот момент.** Перезагрузить вкладку А (F5): блок «Предположение категорий» показывает счётчики и то же предупреждение «Запуск приостановлен: обработано 1 из 3…», а не ошибку с кнопкой «Повторить»; кнопка «Предложить категории» недоступна, потому что запуск активен; опрос продолжается (следующий пункт виден без перезагрузки).
   - **Повторное нажатие.** Во вкладке Б (открыта до запуска, опроса в ней нет, кнопка доступна) нажать «Предложить категории»: «Запуск уже в очереди или выполняется: новый не создан.», строка запуска сразу сменяется на «Запуск приостановлен: обработано 1 из 3…», кнопка становится недоступной. Сообщения «Действие могло выполниться…» быть не должно.
   - **Следующие пакеты.** Второй проход `--once`: в обеих вкладках без перезагрузки «…обработано 2 из 3…». Третий проход (`Classification run 2: succeeded`): «Запуск завершён: предложено 0, не распознано 1, пропущено 2.» — отклонённые на шаге 7 варианты повторно не предлагаются, — список перечитывается сам, кнопка снова доступна, пока «Без категории» больше 0.
   - **Постоянный воркер.** Запустить воркер без `--once` (команда терминала 3 выше, `BATCH_SIZE` по-прежнему `1`) и нажать кнопку: «Запуск поставлен в очередь.», затем за несколько секунд строка проходит «Запуск в очереди и начнётся в ближайшие секунды.» и / или «Модель предлагает категории: обработано X из 3.» (между пакетами при работающем воркере — без слова «приостановлен») и заканчивается «Запуск завершён: …»; пакеты fake мгновенные, поэтому промежуточные строки могут не успеть показаться. Остановить воркер (Ctrl+C).
   - **Пакет выполняется и остановка посреди запуска.** Перезапустить воркер с `--classification-fake-scenario pause` (пакет длится до остановки воркера) и нажать кнопку: «Модель предлагает категории: обработано 0 из 3.». Остановить воркер по Ctrl+C: без перезагрузки — «Запуск приостановлен: обработано 0 из 3. Воркер распознавания не запущен: запуск продолжится, когда воркер запустят.» (запуск начат, но ни один товар не пройден), кнопка недоступна. Чтобы увидеть «Запуск в очереди. Воркер занят другим заданием.», нужен новый запуск в очереди при воркере, занятом распознаванием фото; на этих данных не воспроизводится. Закончить запуск тремя проходами `--once --classification-fake-scenario mixed` либо оставить его в очереди.
9. **Выключенный локальный API.** Остановить `runserver`, выполнить `$env:ALLOW_LOCAL_RECOGNITION_API = "0"` и запустить его снова. `/catalog`, категория, поиск и карточки (`/catalog/products/8`, у товара есть ожидающая запись) работают **без пометок и без сообщений об ошибке**: нет значков, нет блока, нет «Локальный API…», нет кнопки «Повторить» из-за пометок. `/catalog/classification` в обоих блоках сообщает «Локальный API выключен или недоступен с этого адреса…» с кнопкой «Повторить», «Предложить категории» недоступна. То же при остановленном сервере: каталог и карточка показывают только собственную ошибку загрузки, от пометок сообщений нет. Вернуть `1` и перезапустить.
10. **Клавиатура и фокус.** Tab/Shift+Tab по вкладкам раздела, фильтру, кнопке запуска, ссылкам и кнопкам записей; Enter/Space; видимая рамка фокуса. Значок в каталоге и ссылка блока в карточке достижимы Tab, высота области нажатия не меньше 44 px. После действия фокус возвращается на нажатую кнопку, а если она исчезла — на сообщение о результате; при открытии области «Выбрать другой» / «Отклонить» / «Подтвердить все» фокус переходит в область, «Отмена» возвращает его на открывшую кнопку. В области выбора радио переключаются стрелками.
11. **Адаптив и масштаб.** Ширины 320 / 375 / 768 / 1280 px и zoom 200% на экране категорий, в каталоге и карточке: страница не прокручивается по горизонтали, длинные названия («Средство для мытья посуды», «Demo Spülmittel Zitr.») переносятся, значки дублей и категории у одного товара стоят друг под другом и не перекрывают текст, блок карточки не выходит за панель.
12. **Back / Forward и перезагрузка.** Каталог → значок → экран записей товара → название товара → карточка → Back, Back, Forward: адреса и содержимое совпадают, фильтр и `product` сохраняются; «Назад к списку» в карточке, открытой с экрана категорий, возвращает на тот же адрес экрана. Перезагрузка `/catalog/classification?status=all&product=6` открывает тот же вид. `/catalog/classification?status=done` и `?product=abc` — общий экран «Некорректная ссылка».
13. **Screen reader.** Единственный h1 «Категории товаров»; заголовки блоков и групп (h2, h3); у кнопок записей в доступном имени есть название товара («Подтвердить: Demo Toast Weizen»); сообщение о результате и строка запуска объявляются (`role="status"`); в каталоге значок читается как ссылка «Категория: требует подтверждения» сразу после названия товара; блок карточки читается текстом и ссылкой «Открыть в списке категорий».
14. **Админка** `http://127.0.0.1:18000/admin/` (пользователь — `manage.py createsuperuser`): разделы приложения `classification` — «Product classifications», «Classification runs», «Created generic products», «Created categories» — открываются **только на чтение** — нет «Добавить», «Сохранить» и «Удалить». Товар с ожидающей записью (на свежей базе, например №8 «Demo Toast Weizen») **удаляется** обычным подтверждением админки; после этого запись на экране (фильтр «Все») закрыта как «Заменено: товар удалён» при следующем действии или запуске, значка в каталоге нет. Приёмка F4/F6 по `docs/verification.md` — без изменений.

Дополнительно, двумя вкладками с экраном категорий (свежая база либо оставшиеся ожидающие записи):

- **`classification_resolved`**: во вкладке А подтвердить запись, во вкладке Б (без перезагрузки) нажать у неё «Отклонить» → «Да, отклонить» → «Предложение уже решено. Показано актуальное состояние.», список перечитан, ничего не изменено.
- **`classification_changed`**: в админке сменить обобщённый продукт товара с ожидающей записью, затем на экране (без перезагрузки) нажать «Подтвердить» → «Предложение изменилось. Данные обновлены…», открытые области закрыты. В каталоге у такого товара значка нет, в карточке блока нет: его обобщённый продукт уже не равен предложенному.
- **Отказ сети**: в DevTools включить Offline и нажать «Подтвердить» → «Ответ сервера не получен. Действие могло выполниться: проверьте состояние записи перед повтором.»; повтор — только новым нажатием после Online. В каталоге и карточке при Offline от пометок сообщений нет.

## Заход 2 после проверки интерфейса (Ф3, 2026-10-07)

Проверка интерфейса вернула ветку: клиент считал неверным форматом запуск **между пакетами** — `queued` с заполненным `started_at`. Схема `api/product-classifications-schema.ts` требовала у `queued` пустой `started_at`, а сервер возвращает запуск в очередь после каждого пакета и время начала не очищает. Теперь схема Запуска проверяет только то, что сервер гарантирует ([таблица сочетаний](../../../../docs/api-contract.md#допустимые-сочетания-полей-запуска)): `error` есть тогда и только тогда, когда запуск `failed`; `finished_at` — тогда и только тогда, когда статус конечный; `started_at` пуст только у `queued` и `cancelled` и только при `processed = 0`. Счётчики между собой не сравниваются.

Проверено без браузера на окончательном состоянии ветки (команды и числа — [docs/verification.md](../../../../docs/verification.md#фактические-результаты-заход-2-после-проверки-интерфейса-ф3-2026-10-07)):

- Vitest: все 40 эталонов сервера проходят схему, включая пять новых (`status-between-batches.json`, `run-requeued.json`, `run-failed-after-batches.json`, `run-cancelled-started.json`, `run-cancelled.json`); все 13 сочетаний таблицы принимаются; `features/classification/between-batches.test.tsx` ведёт эталон «между пакетами» через настоящий адаптер и `labels.ts` до текста при воркере `idle` / `busy` / `absent`, проверяет открытие страницы в этот момент, опрос каждые 2 с до конца запуска без замедления и `POST runs/` (`created: false`, тот же запуск, обычный текст).
- Настоящий HTTP: `check_product_classifications_proxy.mjs` теперь сам запускает три прохода `recognition_worker --once --classification-fake-scenario mixed` с `PRODUCT_CLASSIFICATION_BATCH_SIZE=1` и читает адаптерами клиента запуск между пакетами (`queued`, `started_at` заполнен, 1 из 3 и 2 из 3), повторный `POST runs/` в этот момент и итог `succeeded`; через Vite dev и preview — exit 0.
- Шаг 8 выше переписан под это поведение. В браузере его по-прежнему проверяет человек.

## Ограничения и непроверенное

- Работа React в браузере не проверялась: клики и ввод, фактический фокус и его возврат, клавиатура, screen reader, вёрстка на узком экране и при zoom 200%, Back/Forward, cookie-политика браузера для CSRF, опрос запуска по времени. Шаги 1–14 выше.
- Итоговая проверка И1 (2026-10-07) на окончательной ветке: 51 файл / 1934 теста, proxy-скрипт через dev и preview, воркер с fake (включая запуск между пакетами) и настоящая модель в QA — [docs/verification.md](../../../../docs/verification.md#фактические-результаты-и1-окончательная-ветка-2026-10-07). Строки ниже описывают, что проверялось в задаче Ф2.
- В задаче Ф2 воркер не запускался. В заходе 2 (Ф3) proxy-скрипт выполняет запуск настоящим воркером с fake по одному пакету: настоящим HTTP проверены состояния «в очереди, воркера нет», «между пакетами, воркера нет» и «завершён». Состояния при работающем воркере (`idle`, `busy`, `running`: «начнётся в ближайшие секунды», «Воркер занят…», «Модель предлагает категории…») проверены только тестами клиента на эталонных ответах. Шаг 8.
- `classification_busy` на настоящем сервере не воспроизводился: нужен импорт чека или слияние в тот же момент. Проверен тестами Ф1 на эталонном ответе.
- Пометки каталога читают одну страницу до 200 ожидающих записей: при большем числе у части товаров значка не будет, пока записи не разобраны. Блок карточки этим не ограничен. Запросы пометок повторяются при каждом открытии списка и карточки, без кеша и без опроса: после решения на экране категорий пометка исчезает при следующем открытии каталога или карточки.
- Пометка зависит от двух независимых ответов (каталог и записи): между ними возможен короткий рассинхрон, который правило совпадения `generic.id` превращает в «без пометки», а не в ложную пометку.
- Удаление товара с ожидающей записью в админке и режим «только чтение» новых моделей проверены серверными тестами шагов С1–С3, в браузере — шаг 14.
- Реальная модель (`codex_cli`) не использовалась.
