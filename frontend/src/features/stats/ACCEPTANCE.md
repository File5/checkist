# Ф7: клиент статистики — приёмка

Три экрана на настоящем API статистики: «Траты за период» (`/stats`), «Почему изменился средний чек» (`/stats/receipts`) и блок «График цен» в карточке товара (`/catalog/products/{id}`). Описание экранов и состояний — [docs/frontend.md](../../../../docs/frontend.md#статистика-траты-средний-чек-и-график-цен-ф1ф7), контракт — [docs/api-contract.md](../../../../docs/api-contract.md#реализовано-статистика-трат-походы-и-ряды-цен-серверная-часть), команды и фактические результаты — [docs/verification.md](../../../../docs/verification.md#статистика-клиент-ф7).

**Интерфейс в браузере агент не открывал**: автоматический обход UI в проекте запрещён. Клики, фокус, клавиатуру, screen reader, узкий экран, Back/Forward и сам вид диаграмм принимает человек по сценарию ниже. Без браузера проверены HTTP-ответы, адаптеры и статическая разметка — [что именно](#проверено-без-браузера).

## Запуск QA-сервера и клиента

Нужна **свежая** QA-база: `migrate`, затем `seed_stats_demo` первым — тогда id совпадают с примерами ниже (категория «Продукты питания» — 1, товар «Demo Frischmilch 1,5% 1L» — 1). Dev-базу не использовать. PowerShell из корня репозитория, `.env` и `backend/.venv` подготовлены по [docs/development.md](../../../../docs/development.md); в **каждом** терминале — весь блок:

```powershell
$env:POSTGRES_DB = "checkist_qa_f7"
$env:POSTGRES_HOST = "127.0.0.1"
$env:POSTGRES_PORT = "25477"
$env:REDIS_PORT = "16477"
$env:CELERY_BROKER_URL = "redis://127.0.0.1:16477/0"
$env:CELERY_RESULT_BACKEND = "redis://127.0.0.1:16477/1"
$env:DJANGO_CACHE_URL = "redis://127.0.0.1:16477/2"
$env:VITE_API_BASE_URL = "/api"
$env:DEV_API_PROXY_TARGET = "http://127.0.0.1:18000"
$env:DJANGO_DEBUG = "1"
$env:ALLOW_LOCAL_RECOGNITION_API = "1"
$env:PRODUCT_MERGE_AUTO_DETECT = "0"
```

Проект `checkist_qa_f7` (Postgres 25477, Redis 16477) — тот, на котором прошла проверка Ф7: его тома сохранены, демо в базе уже есть, `seed_stats_demo` ответит `{"created": false}`. Для полностью нового прогона возьмите другой суффикс и свободные порты, согласованно изменив имя проекта, `POSTGRES_DB` и все URL. Чужие Compose-проекты не останавливайте.

Терминал 1 — сервер:

```powershell
docker compose -p checkist_qa_f7 up -d --wait --wait-timeout 90 postgres redis
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py migrate --noinput
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py seed_stats_demo
./backend/.venv/Scripts/python.exe -X utf8 backend/manage.py runserver 127.0.0.1:18000 --noreload
```

Терминал 2 — клиент (**PowerShell**, не Git Bash: он переписывает `VITE_API_BASE_URL=/api` в путь Windows):

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev -- --port 15173
# либо сборка: npm.cmd run build; npm.cmd run preview -- --port 15173
```

Открыть `http://127.0.0.1:15173/stats`. Воркер распознавания, Celery и `MEDIA_ROOT` для статистики не нужны; `/health` без Celery покажет отказ — к статистике это не относится.

После приёмки остановить свои `runserver` и Vite, затем `docker compose -p checkist_qa_f7 down` **без** `-v`: тома сохраняются.

## Ручной сценарий (человек)

### 1. Траты за период — `/stats`

1. В шапке есть «Статистика»; под ней — «Траты» и «Средний чек». Открыть `http://127.0.0.1:15173/stats`: заголовок «Траты по категориям», два блока — EUR и KZT, у каждого свой итог и своя круговая диаграмма; над блоками сказано, что валюты не складываются. Числа — из таблицы выше.
2. Диаграмма: наведение на сектор выделяет его и показывает в центре название, сумму и долю; под диаграммой — таблица с теми же значениями. Сектор и строка таблицы категории — ссылки.
3. Drill-down: нажать «Продукты питания» → адрес получает `category=1`, появляются путь («хлебные крошки») и «На уровень выше», итог называется «Сумма строк товаров», под блоком объяснено, почему сумма чеков не показывается. Нажать «Молочные продукты» → ещё уровень. Перейти до обобщённого продукта и товаров; строка товара ведёт в его карточку.
4. Back браузера возвращает по одному уровню с прежними числами, Forward — вперёд; «На уровень выше» и ссылки пути делают то же без истории. Перезагрузка страницы на любом уровне показывает тот же уровень.
5. Разбивка: «Категории», «Обобщённые продукты», «Товары», «Магазины». Внутри категории (`/stats?category=1&currency=EUR`) переключить на «Обобщённые продукты» — экран показывает десять обобщённых продуктов категории, путь с «Продукты питания» остаётся (ответ сервера с `parent` при `group_by=generic`). «Магазины» — у магазинов нет строк «без товара / услуги / залог», итог равен сумме чеков.
6. Фильтры: быстрый выбор периода («Этот месяц», «Прошлый месяц», «Этот год», «Прошлый год», «Всё время»), две даты, страна, валюта, магазины (до 20). «Применить фильтры» меняет адрес; «Сбросить фильтры» убирает фильтры и оставляет место в drill-down. Валюта EUR оставляет один блок. Период `2018-01-01` — `2018-12-31` — «По выбранным фильтрам трат нет» со ссылкой сброса. День `2026-03-14` — одна отрицательная сумма (возврат): диаграммы нет, значение в таблице, доля не считается.
7. Дата начала позже даты конца — ошибки у полей, фокус на первом ошибочном, запрос не уходит. Адрес `/stats?store=99` (магазина нет) — сервер отвечает `400`, экран сообщает, что параметры не приняты, и отмечает поле магазинов; непонятные значения вроде `country=de1` отбрасываются ещё при разборе адреса.
8. «Не разобрано» и строки без товара показаны как есть, рядом подсказка про назначение категории в админке.

### 2. Почему изменился средний чек — `/stats/receipts`

1. Открыть `http://127.0.0.1:15173/stats/receipts`: форма двух периодов, блок сравнения просит выбрать периоды, ниже — график «Средний чек по времени» за всю историю (по месяцам), отдельно EUR и KZT.
2. Открыть `http://127.0.0.1:15173/stats/receipts?base_from=2020-01-01&base_to=2020-12-31&current_from=2026-01-01&current_to=2026-09-30` (или задать эти даты в форме и нажать «Сравнить периоды»). В блоке EUR: вывод словами, средний чек 27,01 → 45,72, изменение +18,71 = количество 8,65 + цены 7,39 + состав 2,67 (в таблице слагаемых и полосой над ней), индекс цен 1,2404 с покрытием, таблица товаров, купленных в обоих периодах. В блоке KZT — свои числа из таблицы выше; валюты не складываются.
3. Быстрый выбор «2020 против этого года (2026)» даёт те же периоды с концом на сегодняшней дате браузера: средний чек и слагаемые те же (демо кончается в сентябре 2026).
4. Интервал графика: «Месяц», «Квартал», «Год» — меняется только график, блок сравнения не перезагружается и не мигает. На интервале «Год» значения EUR — из строки «по годам» таблицы выше. Под графиком — «Таблица значений» с теми же числами.
5. Базовый период, пересекающийся с текущим (конец базового `2026-01-01`), — ошибка у поля, сравнение не строится, график остаётся. Периоды `2017` и `2018` — «походов нет». Период только в 2018 против сентября 2026, валюта KZT — сравнение без разложения (походы в одном периоде), с объяснением.
6. Название товара в таблице ведёт в карточку товара.

### 3. График цен — карточка товара

1. Открыть `http://127.0.0.1:15173/catalog/products/1?date_from=2025-01-01` («Demo Frischmilch 1,5% 1L», обобщённый продукт «Молоко»). Блок «График цен» стоит рядом с прежними таблицей истории и сводкой — они не изменились.
2. Две панели — EUR и KZT (валюты на одной оси не смешиваются): ряд этого товара по магазину «Zahlenfrisch» и ряды похожих товаров по странам — Германия (DE/EUR) и Казахстан (KZ/KZT). Значения — из последней строки таблицы выше.
3. Переключение серий: флажки «Серии на графике» прячут и возвращают линию; при всех выключенных — «Все серии скрыты». Смена интервала или цены сохраняет выбор серий. Флажок «Показывать похожие товары» убирает ряды других товаров (остаётся одна панель EUR).
4. «Цена»: «За единицу в чеке» / «За кг / л / шт»; «Интервал»: «Месяц» / «Неделя» / «День». Выбор попадает в адрес (`price`, `interval`) и переживает перезагрузку; страница таблицы истории при этом не сбрасывается.
5. Наведение показывает вертикальную линию и значения всех видимых рядов за интервал; «Таблица значений» под графиком раскрывается.
6. Товар 6 («Demo Äpfel lose»), «За кг / л / шт» — два своих ряда по двум магазинам. Товар 11 («Demo Butterkeks») — обобщённый продукт «Не разобрано»: похожих нет, есть объяснение. Товар 1 с периодом до `2018-12-31` — «нет наблюдений» и сброс фильтров. Адрес `/catalog/products/999999` — «Товар не найден».
7. Фильтры карточки «магазин», «страна», «валюта» меняют таблицу истории и сводку, но **не** график: он берёт из них только период (об этом сказано в блоке).

### 4. Клавиатура и фокус

1. Tab проходит шапку, «К содержимому», переключатели раздела, быстрые периоды, поля формы, разбивку, путь, ссылки таблицы под диаграммой; фокус везде виден. Секторы круговой диаграммы в порядок Tab не входят — те же ссылки есть в таблице.
2. Линейный график — одна остановка Tab: ← и → — соседний интервал, Home и End — первый и последний, Esc — снять выделение; значения выделенного интервала читаются под графиком. Флажки серий и радиокнопки «Цена» / «Интервал» работают пробелом и стрелками.
3. После применения фильтров или перехода по drill-down фокус не прыгает в начало страницы: при смене только параметров адреса он остаётся на нажатом элементе либо переходит на заголовок обновлённого блока. При ошибке формы фокус — на первом ошибочном поле.
4. Screen reader: у диаграмм есть названия, значения доступны таблицами (`caption`, заголовки столбцов), состояния «Загружаем…» и ошибки объявляются.

### 5. Выключенный флаг, пустая база, отказы

1. Остановить сервер, задать `$env:ALLOW_LOCAL_RECOGNITION_API = "0"`, запустить снова. `/stats` и оба блока `/stats/receipts` показывают «Локальный режим выключен…» без кнопки повтора (сервер отвечает `403 permission_denied`); формы фильтров остаются. График цен в карточке товара **работает**: его эндпоинт открыт, как каталог. Вернуть `1` и перезапустить сервер.
2. Пустая база: другой проект с новым томом, только `migrate` без `seed_stats_demo`. `/stats` — «Чеков пока нет…» со ссылкой «Загрузить фото»; `/stats/receipts` — график сообщает, что чеков пока нет, сравнение любых периодов — «походов нет»; списки магазинов пусты, формы работают.
3. Остановить сервер при открытой странице и нажать «Применить фильтры»: ошибка с кнопкой «Повторить», прежние данные не выдаются за новые; после запуска сервера «Повторить» загружает данные. На `/stats/receipts` отказ одного блока не убирает второй.
4. Медленная сеть (DevTools → Slow 3G): при смене фильтра прежний результат трат остаётся приглушённым с «Обновляем данные…»; быстрые два переключения не оставляют на экране ответ первого.

### 6. Узкое окно и масштаб

Ширина 320, 375, 768 и 1280 px, масштаб 200 %: страница не прокручивается по горизонтали, широкие таблицы (товары сравнения, значения графика) прокручиваются внутри своей области, подписи диаграмм не обрезают действия, формы складываются в одну колонку. При системной настройке «уменьшить движение» выделение секторов и точек не анимируется.

## Ограничения и непроверенное

- **Браузер не открывался.** Вид диаграмм, наведение, клавиатура, фокус, screen reader, узкое окно, Back/Forward, медленная сеть — только ручной сценарий выше.
- **График цен берёт из фильтров карточки только период.** Магазин, страна и валюта карточки на него не влияют; параметр `country` эндпоинта экран не использует.
- **Список магазинов в формах — не весь справочник.** Средний чек: первые 50 магазинов (выбранной страны, если она задана); траты: первые 200. Когда магазинов больше, форма сообщает об этом; поиска по магазинам в формах статистики нет. Магазин из адреса, которого нет в списке, показывается строкой с id и снимается.
- **Только светлая тема.** Тёмной темы в приложении нет, `prefers-color-scheme` не учитывается.
- Интервал «Неделя» на экране среднего чека предлагается только когда он уже есть в адресе (`interval=week`).
- Валюты не пересчитываются: общего итога по EUR и KZT нет намеренно.
- `400 range_too_large` и `503` настоящим HTTP не проверялись (на демо недостижимы); покрыты тестами сервера и клиента.
- Время ответа на базе больше демо не измерялось.
