# F3: каталог и категория — передача для ручной приёмки

Реализованы компоненты настоящего интерфейса. В этой ветке App ещё показывает заглушки F2: подключение принадлежит F5. Этот документ — сценарий проверки и отчёт, а не скриншот или визуальный макет. Данные в runtime поступают только из API; демонстрационные товары и подмена fetch в продукт не добавлены.

## Подключение в F5

Экспорты совпадают с `src/pages/types.ts`; страницы рендерятся под единственным h1 оболочки:

```tsx
import { CatalogPage } from './features/catalog/CatalogPage'
import { CategoryPage } from './features/catalog/CategoryPage'

// route.kind === 'catalog'
<CatalogPage query={route.query} />
// route.kind === 'category'
<CategoryPage categoryId={route.categoryId} query={route.query} />
```

В обоих файлах также есть default export. Каждая страница импортирует `Catalog.css`. CSS использует префикс `ck-catalog-`, общие RequestState/Pagination и навигацию F2. Props, API F1, App и общие стили не менялись.

`/catalog` показывает дерево из `/api/categories/`, поиск и серверный список всех товаров. Дерево строится по серверным path/depth, счётчики — products_total. Категория показывает крошки, непосредственные подкатегории, generic_products своего узла и товары всей ветви. Search/generic/page хранятся в query URL; поиск отправляется кнопкой/Enter, generic меняется сразу. Смена фильтров сбрасывает page в 1. Пустая поисковая строка снимает q.

Строки товара содержат ссылку, бренд, фасовку, обобщённый продукт и последние покупки для каждой пары страна/валюта с локальной календарной датой. Decimal форматируется функциями F1 без Number. Нет бренда/фасовки — «Не указано», нет наблюдений — «Покупок пока нет». Это не текущий прайс магазина.

Запросы дерева, категории и товаров имеют отдельные состояния и повторы. AbortController/generation guard отменяют предыдущий запрос и исключают поздние ответы. Новые параметры сразу дают loading, старые строки не выдаются за новые. UI не показывает серверные сообщения. 400 предлагает исправить поле/сбросить параметры, 404 категории — каталог, page_out_of_range — первую страницу с сохранёнными фильтрами через replace. Автоматических повторов нет.

## Проверено и прошло

2026-10-04; Windows, Node `v24.18.0`, npm `11.16.0`. Только frontend/Node, БД и Compose не запускались. Команды выполнялись в `frontend/`:

- `npm.cmd ci` — exit 0; 188 пакетов, 0 уязвимостей. Предупреждение deprecated для закреплённого ESLint; зависимости и lock не менялись.
- `npm.cmd run lint` — exit 0.
- `npm.cmd run test` — exit 0; 14 файлов, 445 тестов. Из них 39 новых тестов F3: переходы query и построение запросов, дерево с циклическим parent_id, валидация Unicode, пустые/ошибочные состояния, отмена/поздний ответ/повтор и адаптер с mocked fetch. Node server-render проверяет HTML-семантику ссылок, подписей, пагинации и nullable-полей; он не подтверждает поведение React в браузере.
- `npm.cmd run build` — exit 0; TypeScript проверяет исходники F3, Vite собирает текущий App с заглушками F2. До подключения F5 feature-страницы не входят в bundle App.
- `git diff --check`, затем после `git add -A` — `git diff --cached --check`: оба exit 0. Все 15 добавленных файлов находятся только в `frontend/src/features/catalog/`.

## Проверено и не прошло

Первый `npm.cmd run test` — exit 1: 1 из 434 тестов упал на одиночном UTF-16-суррогате в поиске. `URLSearchParams` заменял его до валидации. Причина исправлена: исходный ввод проверяется перед кодированием. Ожидание теста сохранено, окончательные 445 тестов прошли. Неустранённых отказов проверок нет.

## Не проверено и почему

Настоящий HTTP каталога/QA-БД недоступен в текущей ветке: backend `5e1adfa` не слит. Соседний worktree не запускался и не менялся. API/mock tests, типизация и статический аудит не заменяют интеграцию.

Визуальное и интерактивное поведение React, Back/Forward/reload, клавиатура, фокус, screen reader, адаптив и zoom проверяет человек после подключения в F5 и подготовки QA. Автоматический обход UI не выполнялся, скриншотов нет. Локальное превью F3 не создано, поскольку App принадлежит F5 и сейчас содержит заглушки. Markdown передаётся для показа ограничений и воспроизводимых сценариев. Публикация, merge, production и backend-проверки не выполнялись.

## Сценарий проверки человеком

После подключения F5 и подготовки собственного QA API по `docs/verification.md` / согласованному подготовительному ответу применить **весь QA environment-блок** в каждом терминале (checkist_qa, Postgres 25432, Redis 16379, API 18000, proxy target 18000, VITE_API_BASE_URL=/api). Не использовать dev-данные и не останавливать чужие процессы. В `frontend/` выполнить `npm.cmd ci`, `npm.cmd run dev -- --port 15173`; для preview сначала build, затем остановить dev и выполнить `npm.cmd run preview -- --port 15173`.

ID брать из настоящего QA API. Для пагинации нужны >50 подходящих товаров; для других сценариев — пустая категория, пустая ветвь с подкатегориями, товар без бренда/фасовки/наблюдений, длинные названия, несколько валют. Эти записи в F3 не создавались. Для контролируемых 400/500/ошибок схемы допускается ручная подмена ответа через DevTools/QA proxy без правки кода; mocked ответы не считать проверкой настоящего сервера.

1. Открыть `/catalog`: загрузка дерева и товаров → обычные вложенные списки категорий и строки товаров. Сверить products_total с API, особенно родитель с товарами только у потомков. Перейти в категорию: крошки соответствуют серверному path, название узла видно, подкатегории доступны. Товары потомков включены без дополнительного запроса для каждого узла.
2. Ввести один символ: появляется подсказка, «Найти»/Enter возвращает фокус в поле, нового запроса нет. Проверить 2 и 100 Unicode-символов, 101 символ, пробелы по краям. Набрать допустимый q и нажать Enter/«Найти»: q сохраняется в адресе. Очистить и отправить — q исчезает. До отправки ввод не запускает поиск.
3. В категории выбрать generic: URL содержит generic, поиск ограничен category и generic, page сброшен. Перейти на другую страницу, изменить q/generic: page становится 1. Reload, Back/Forward восстанавливают URL, значение input/select и результаты. Неотправленный черновик не должен заменять восстановленный q. Generic с ID, которого нет в узле, явно показан отдельным выбранным вариантом; фильтр не сбрасывается молча.
4. По товару открыть `/catalog/products/:id`, вернуться средствами F4/Back: исходный контекст списка сохранён F2. Проверить даты и валюты, нулевую/отрицательную цену; отсутствующие поля не становятся нулём. «Последняя покупка» не представлена текущим предложением магазина.
5. Проверить пустой каталог, пустую категорию без детей, ветвь без товаров с детьми («Выберите подкатегорию»), поиск/фильтр без результатов («Ничего не найдено» и сброс). Сброс сохраняет category и снимает q/generic/page.
6. Несуществующий ID категории: «Не найдено» и «В каталог». В существующей категории добавить `page=999999`: предложена первая страница, q/generic сохранены, действие заменяет ошибочную запись History. 400: локальные подписи ошибок у q/generic по fields, исправление/сброс, кнопки повторения того же запроса нет. Серверный message и значения fields не показываются.
7. Offline/500/невалидный JSON/схема: ошибка соответствующего блока и «Повторить». При отказе товаров подкатегории/форма остаются, при отказе дерева список товаров остаётся. Online → повтор восстанавливает блок. Замедление >15 секунд даёт timeout. Клавиатурный повтор переводит фокус в стабильный заголовок/контейнер, кнопка не оставляет фокус на удалённом элементе.
8. Замедлить сеть; быстро менять q/generic/page и category, затем уйти в health/товар. Последний запрос побеждает; поздние успех/ошибка не заменяют новый результат. Уход не даёт сообщения об ошибке. Повторить в StrictMode. Проверить независимый повтор дерева и списка.
9. Tab/Shift+Tab, поиск Enter, select стрелками, кнопки Space/Enter, ссылки Enter/Ctrl-клик/средняя кнопка. Query-обновления сохраняют фокус формы, сброс возвращает его в input, переход страницы списка — в заголовок результатов; pathname — в h1 оболочки F2. Screen reader: labels и описания ошибок, крошки, текущая страница, loading/результаты объявляются понятно.
10. Ширины 320/375/540/768/1280 px, zoom 200%, длинные названия и максимальные суммы: текст переносится, input/select/действия доступны, нет горизонтальной прокрутки страницы. На ≤540 px форма/строки/метаданные/ссылки категорий в одну колонку. Вертикальной прокруткой владеет страница; глубина дерева не увеличивает отступ бесконечно. При reduced motion нет анимаций. Проверить смену loading/ошибки/успеха без скрытых действий и фиксированного обрезания высоты.

После приёмки остановить свои Vite/preview/runserver; если создавалась собственная QA — `docker compose -p checkist_qa down` без `-v` по правилам проекта. Этот этап не подтверждает ручную приёмку: её результаты фиксирует F5/человек.
