# R2: локальный клавиатурный фокус

Исправлены локальные потери фокуса при повторе запросов, пагинации и исчезновении действий. Реализован общий `useLocalRequestFocus` с тестируемым контроллером в `src/components/`, без новых зависимостей. Интерфейс использует настоящие API-адаптеры, тестовые данные в продукт не добавлены.

## Найденные места и исправления

| Место | Причина в исходниках | Исправление |
| --- | --- | --- |
| CatalogPage: дерево категорий | Повтор вручную фокусировал h2 до запроса, но после повторной ошибки фокус не возвращался на кнопку | Стабильный h2, общий механизм loading → h2, повторная ошибка → локальная кнопка, успех → h2 |
| CategoryPage: сведения категории | Loading/error заменяли всё содержимое; общий контейнер охватывал и чужой запрос товаров, восстановление после ответа отсутствовало | Независимая постоянная секция сведений и h2 во всех состояниях; товары имеют свою область фокуса |
| ProductsSection: все товары и товары категории | Пагинация исчезала; эффект фокусировал h2 по query без проверки текущего фокуса; повтор оставлял фокус на h2 даже при новой ошибке; ссылки сброса/первой страницы могли исчезать | Общий механизм вместо безусловного эффекта; локальный повтор, страницы, сброс результата и первая страница сохраняют свой h2/повтор |
| ProductPage: карточка | Кнопка повтора удалялась на loading; постоянный h2 не принимал фокус; not_found удалял всю секцию | Карточка и focusable h2 устойчивы, включая ответ not_found; локальное восстановление, остальные запросы не управляют её фокусом |
| PriceHistory | Был безусловный перенос при смене page и однократный при повторе; повторная ошибка не восстанавливала кнопку; действия сброса/первой страницы исчезали | Общий механизм для повтора, страниц, page_out_of_range и сброса из результата; формы сохраняют свой фокус |
| PriceSummary | Повтор/сброс удаляли нажатую кнопку; h2 не принимал фокус | Постоянный focusable h2 и независимая область восстановления |
| StoreFilter | Повтор и кнопки страниц удалялись на loading; сброс поиска, первая страница, «Убрать магазин» также могли удалить активную кнопку; select становится недоступным при отказе | Постоянный focusable legend «Магазин», восстановление только в fieldset; доступный устойчивый контрол/поле не теряет фокус |
| CatalogSearch и форма товара | Поля/основные кнопки устойчивы; сброс каталога уже возвращал фокус в input | Эти решения сохранены; общий механизм результатов не перехватывает фокус у формы, поиск по Enter не прерывается |

Текущие кнопки страниц справочника исчезают на loading, поэтому цель — legend «Магазин». После ответа фокус остаётся там. Устойчивый доступный контрол сохраняет фокус; удалённый/недоступный передаёт его локальной цели. После повторной ошибки повтора цель — доступная «Повторить» своего блока; при ошибке без повтора остаётся заголовок. Первый ответ без локального взаимодействия не переносит фокус.

Уход в другой блок отменяет ожидание, даже если затем фокус оказался на body. Ввод в устойчивом поле того же блока тоже не перехватывается. Хук принимает только React commit с актуальным состоянием; AbortController/generation guards запросов сохранены. Unmount удаляет listener и отменяет локальное ожидание. App/F2 и навигация не изменены: pathname → h1, query сохраняет фокус, возврат к выбранному товару остаётся за App.

Существующий `[tabindex]:focus-visible` даёт синюю рамку новым целям. Дополнительных aria-live/role=status нет; прежние сообщения и aria-busy сохранены. При уже активной цели повторный focus не вызывается. CSS, зависимости и backend не менялись.

Среда: Windows / PowerShell, Node `v24.18.0`, npm `11.16.0`. Все команды npm — из `frontend/`. Vitest использует Node, контроллеры запросов и искусственные элементы без DOM; разметка — React SSR. БД/настоящий API не использовались.

## Проверено и не прошло

Первый `npm.cmd run test` после добавления контроллера — exit 1: 506 прошли, один прежний `scripts/app.test.tsx` не прошёл. Он ожидал соседние атрибуты `id="product-history-heading" tabindex="-1"`; новая data-метка была вставлена между ними. Порядок атрибутов компонента исправлен, существующее ожидание не менялось. Повторный полный прогон — 524/524, exit 0. Проверки не отключались и ожидания не ослаблялись.

## Не проверено и почему

- Реальный DOM-фокус, прокрутка, клавиатура, native select, screen reader, адаптив и zoom: по правилам проекта принимает человек. Автоматического обхода UI/браузерного раннера и скриншотов нет. Эта сдача содержит настоящий код и Markdown-сценарий; статический макет не создавался.
- Настоящие HTTP/proxy и расширенные QA-данные >50 магазинов/товаров/наблюдений не запускались: исправляется frontend-фокус; обязательные проверки выполнены на Node/SSR/типизации/сборке. Старые результаты F6 не засчитываются как результаты R2.
- Build подтверждает сборку и типы, SSR — разметку, контроллерные тесты — решения о фокусе и guard. Фактическое поведение браузера они не подтверждают. Merge/publish/deployment не выполнялись; свои серверы и контейнеры в этой задаче не создавались.

## Ручная приёмка человеком

Полный сценарий с блокировками **каждого** запроса и конкретными целями фокуса добавлен в [docs/frontend.md](../docs/frontend.md#клавиатурная-приёмка-локального-фокуса-r2). Подготовка изолированной QA и команды API/Vite — в том же документе. Не использовать dev/локальный Postgres; базовые образцы F6 недостаточны для UI-пагинации, нужны >50 подходящих записей.

1. После подготовки QA, в терминале с полным QA environment выполнить в `frontend/` `npm.cmd run dev -- --port 15173`; открыть `http://127.0.0.1:15173/catalog`. Для сборки вместо dev: `npm.cmd run preview -- --port 15173`, при остановленном dev.
2. Для дерева, сведений категории, общего списка, товаров категории, карточки, истории, сводки и магазинов по очереди вручную заблокировать только свой API-запрос в DevTools, reload. Tab/Shift+Tab → «Повторить», Enter/Space: loading → локальный h2 (для магазинов legend), новая ошибка → локальная «Повторить». Снять блокировку, вернуть фокус на кнопку и повторить: loading/успех → тот же h2/legend. Не должно быть перехода на body/h1/соседний блок.
3. На >50 магазинах перейти «Следующие магазины»/«Предыдущие магазины» клавишей Enter; на loading и после ответа фокус на legend «Магазин». Следующий Tab/Shift+Tab продолжает работу рядом с выбором магазина. Проверить первую/последнюю страницу и недоступные кнопки. Ссылка страницы товаров/истории → собственный h2 результата.
4. `?page=999999` → `page_out_of_range` → Enter «На первую страницу»: свой h2. Для справочника нужна отдельная QA-ситуация уменьшения набора между запросами; если она не подготовлена, отметить вариант как непроверенный. Проверить «Сбросить фильтры» из пустых результатов → свой h2; из формы каталога → input; применение/сброс формы товара → устойчивая кнопка. Поиск Enter → поле поиска до/после ответа. Исчезающие «Сбросить поиск магазинов»/«Убрать магазин» → legend.
5. В Slow network после повтора/пагинации перевести фокус в другой блок либо поле поиска своего блока до ответа: успех/ошибка его не забирают. Быстро менять query/фильтры и уходить: отменённый/старый ответ не меняет фокус. Переход маршрута → h1; возврат в список → выбранный товар после загрузки, если фокус не уведён.
6. Screen reader, 320/375/768/1280 px, zoom 200%, длинные тексты: синяя рамка видима, действия доступны, нет лишних live-объявлений, горизонтальный scroll только в таблице. После приёмки снять блокировки, остановить свои Vite/API и выполнить `docker compose -p checkist_qa down` без `-v`, если поднимали свою QA.
