# Трекер трат: план двух волн (2026-10-13)

Решения человека (интервью 2026-10-13). Траты — главное; **доходы человек вносит сам** (волна 2, из выписок не
берутся); счетов и остатков нет. Несколько семей по
приглашению, веб-приложение (PWA) с push, курсы Нацбанка РК. Работа — две волны параллельных агентов, у каждого своя
ветка и worktree; сливает и выкладывает ведущий. Правки данных на проде — только после «да» человека.

## Волна 1

| № | ветка | что |
|---|---|---|
| 1 | `feature/smart-expense` | Новая трата: калькулятор в поле суммы (`1200+350`, разряды при вводе); подсказки из истории во время ввода (без модели, одно касание = повтор с сегодняшней датой); разбор словами получает 10 похожих прошлых трат и список магазинов семьи (модель берёт существующий магазин, категорию, валюту, без суммы в тексте — последнюю сумму); склейка магазинов с вариантами написания (предлагают похожесть и модель, подтверждает человек). Строки ручных трат с товарами каталога **не** связываются. |
| 2 | `feature/recurring` | Регулярные платежи: шаблоны (предложения по истории — тот же получатель и похожая сумма 3 месяца подряд — и вручную); оплачен ли в месяце — сверкой с тратами при чтении; на Главной «Осталось оплатить»; с 1-го числа вопрос по неоплаченным прошлого месяца «добавить по средней / не было / оплачено иначе» — сам ничего не добавляет. Рост суммы («было 200 $, стало 225 $») — у шаблона. |
| 3 | `feature/statement-import` | Импорт выписок Kaspi Gold и ForteBank (PDF): черновик со списком, узнанные отмечены, спорные подсвечены, дубли с уже внесёнными тратами убраны, «Сохранить N трат»; правила «получатель → категория» учатся на правках человека + экран правил; переводы людям пропускаются, кроме названных правилом; незнакомые строки — модели через очередь `recognition_worker`; PDF **не хранится** — только SHA-256 файла (повтор не задваивает). Каждый член семьи грузит свою выписку, траты — на него. Вход — «Загрузить выписку» в листе «＋». |
| 4 | `feature/currency-rates` | Курсы Нацбанка РК на дату траты (выходные — последний опубликованный; загрузка задним числом для старых трат); основная валюта семьи = `Profile.default_currency` главного (без семьи — своя; иначе KZT); итоги Главной, статистики и лимитов — в основной валюте, исходная сумма сохраняется («20 $ · ≈ 9 640 ₸»); лимиты задаются только в основной валюте. |
| 5 | `feature/families` | Приглашение «новая семья» (приглашённый создаёт учётную запись и становится главным своей новой семьи; выдаёт администратор/главный нашей); ИИ у семьи: включатель (новые семьи — выключен, существующие — включён) и дневная квота (по умолчанию 50 запросов), правило — одна функция `accounts.ai`. Дерево категорий общее. |

## Волна 2 (после слияния волны 1)

Траты и Главная (строка «поиск / вопрос», свайп и «Отменить», «можно тратить в день» = (бюджет месяца или Σ лимитов −
потрачено − неоплаченные регулярные) / оставшиеся дни, общий бюджет месяца над лимитами, история лимитов прошлых
месяцев); push (регулярный скоро/просрочен, лимит 80/100 %, сводка по воскресеньям, разбор месяца 1-го, крупная трата
другого члена семьи — выключено, порог 100 000 ₸; тишина 22–9; настройки у каждого); цели (общие и личные — личную видят
владелец и главный; взносы вручную и из выписки по правилу «перевод на свой депозит → цель»); ИИ (разбор месяца,
ответы на вопросы).

Доходы (пятый агент волны 2): вносятся только вручную — в форме траты переключатель «Трата / Доход» (тот же калькулятор,
разбор словами сам понимает «зарплата 650 000»); регулярный доход — шаблоны `recurring` с видом «доход» («Зарплата
650 000 ₸ — внести?» одним касанием, сумму можно поправить); свой короткий список категорий (Зарплата · Подработка ·
Подарки · Кэшбэк и проценты · Продажа вещей · Прочее + свои), в дерево трат не смешивается; записи видят автор и главный,
остальные — только общий доход семьи за месяц; Главная — «Доход N · Потрачено M · Отложено K (x %)», пока дохода нет —
«Доход не внесён — добавить» (не 0); «можно тратить в день» без бюджета и лимитов — от дохода минус неоплаченные
регулярные; «Динамика» — линия дохода и «отложено» по месяцам; цели — «в среднем откладываете N, до цели ~X месяцев».
Валюта — как у трат (в основную по курсу дня); выгрузка JSON включает доходы. Поступления из выписок в доходы не идут
(импорт хранит их только пропущенными строками черновика).

**Общие точки** (не переписывать чужое):

- Магазин по имени — только `receipts.manual.find_or_create_store(name, currency)`; smart-expense добавляет туда
  варианты написания. Импорт выписок создаёт траты только через `receipts.manual.create(owner, data)` с `store_name`.
- `receipts/manual_parse.py`: smart-expense меняет `build_input` и промпт; families добавляет одну проверку ИИ в начало
  `request()` и больше файл не трогает.
- `recognition_worker.py`: statement-import добавляет свою очередь отдельным шагом цикла; остальные не трогают.
- Импорт выписок проверяет право на ИИ своей заглушкой `_ai_allowed(user)` (ведущий при слиянии заменит на `accounts.ai`).
- Курсы: currency-rates даёт `rates.convert.to_base(amount, currency_code, day, user) -> Decimal | None` и
  `rates.convert.base_currency(user) -> str`; в волне 1 остальные их не вызывают.
- Регулярные: recurring даёт `recurring.services.unpaid(user, month)` (ожидаемая сумма и валюта каждого неоплаченного)
  — для волны 2; оплачен ли — сверка при чтении, без сигналов и правок в `receipts`.
- `features/dashboard/DashboardPage.tsx`: recurring добавляет **одну строку** `<RecurringDue month={data.month} />` после
  `<Actions />` (компонент — в `features/recurring/`); остальные правки Главной — только currency-rates.
- `menu/MainMenu.tsx`: statement-import добавляет пункт «Загрузить выписку» в лист «＋»; пункты «Ещё»
  (`menu/menu-items.ts`) и маршруты (`navigation/routes.ts`, `App.tsx`) добавляют все — по строке, конфликты разрешает
  ведущий.
- `CLAUDE.md` агенты не меняют — абзац для него пишут в отчёте. В `docs/*.md` — свой раздел в конце файла.
- Цвета — только токены `tokens.css`; новые токены — в конце своим блоком с именем ветки. Новые экраны — кирпичи
  `.ck-panel` / `.ck-list` / `.ck-row`, главное действие — `--ck-primary`, порог телефона 540 px.
